# FORM — локальний SVG → 3D прототип

Завантаження SVG, об’єм із внутрішньою фаскою, обертання мишею, масштаб колесом, скло/метал/хром, кольори, світло, 5 пропорцій і справжній Blender Cycles export у PNG/JPG.

## Запуск на цьому комп’ютері

```powershell
Set-Location 'D:\3D Graphic'
npm.cmd run dev
```

Відкрити [локальний редактор](http://127.0.0.1:4173). Сервер слухає тільки loopback. Якщо він уже запущений, другий запуск не потрібен. Завершення — Ctrl+C у терміналі сервера.

Доступний portable Blender: `.local/tools/blender-4.3.2-windows-x64/blender.exe`. Для іншої інсталяції перед запуском встановіть `$env:BLENDER_PATH` на повний шлях до blender.exe. Python-залежності worker лежать у `.local/python`; потрібні wheels під Python 3.11 Blender 4.3.2.

Для чистого середовища: Node.js 24, `npm.cmd ci`, Blender 4.3.2 з [офіційного каталогу](https://download.blender.org/release/Blender4.3/), Python 3.11. Встановлення Python-залежностей:

```powershell
python -m pip install --target .local/python -r workers/render/requirements.txt
```

Використовуйте Python 3.11 або pip з `--python-version 311 --only-binary=:all:` для сумісних wheels. Усі залежності локальні. Архів Blender не входить у Git.

## Робота

1. Почніть з демонстраційного знака або завантажте SVG із замкнутими залитими контурами.
2. Виберіть матеріал, колір, глибину та фаску. Перетягування в canvas обертає об’єкт.
3. Виберіть пропорції. Матеріал, світло, фон, об’єм і ракурс одразу перераховуються у живому WebGL-перегляді.
4. «Скачати кадр» зберігає точну копію живого WebGL-фрейму, а «Скачати 4К» рендерить ту саму raster WebGL-сцену у 3840 px без запуску Cycles.

Кожен WebGL-експорт отримує snapshot поточного framebuffer; наступні зміни не впливають на кадр, який кодується. Cycles використовується окремо для майбутнього режиму максимальної якості, а не для швидкого завантаження. JPG завжди без alpha. Скло у transparent PNG має обмеження композиції.

Інтерактивний перегляд малює після змін і призупиняється у прихованій вкладці. Pixel ratio обмежено 1 для зменшення витрат GPU на екранах високої щільності; розміри фінального експорту не змінюються. У dev-режимі атрибут `data-render-count` на canvas дозволяє перевірити, що лічильник кадрів не зростає у спокої. Фінальний Cycles-процес запускається лише кнопкою експорту.

## Перевірки

```powershell
npm.cmd test
npm.cmd run build
```

Build включає TypeScript typecheck. Unit tests перевіряють замкнутість mesh, отвори, фаски, стабільність геометрії, відхилення небезпечних/непідтримуваних SVG та контракт сцени. Результати реальних рендерів і метрики лежать у `.local/jobs/<id>/` (input.json, mesh.json, result.png/jpg, metrics.json, render.log).

## Важливі межі

Це локальний технічний зріз, не готовий production MVP. Немає бібліотеки текстур/HDRI, проєктів, акаунтів, undo/redo, серверної черги й анімації. Геометрія скидається після перезапуску. Файли результатів залишаються на диску. Поточний runtime mesh transport — JSON, не GLB.

Імпорт обмежено 2000 сегментами; stroke, text, CSS stylesheets, masks, gradients, відкриті контури й перекриття відхиляються. Складна або завелика фаска повертає помилку. Швидкий WebGL-перегляд приблизний; інтенсивність світла між рушіями ще потребує калібрування. Не використовуйте його як гарантію вигляду скла.

Готові рендери відновлюються з диска при запуску сервера й доступні за попередніми job URL; незавершені jobs не відновлюються. Сам редактор не зберігає поточну сцену після оновлення сторінки.

`npm.cmd run test:integration` потребує запущеного сервера: виконує реальний preview, перевіряє HTTP-завантаження та скасування. `npm.cmd run test:4k` запускає реальний 4К-рендер і повертає його ID; завершення перевіряється через GET job. Обидві команди використовують GPU й записують результати в .local.

Фактичні результати й відкриті перевірки: [PROTOTYPE_RESULTS.md](docs/PROTOTYPE_RESULTS.md).

Докладні відхилення прототипу від цільового MVP: [рішення 0001](docs/decisions/0001-local-prototype.md). Початкова архітектура: [ARCHITECTURE.md](ARCHITECTURE.md).

## Публікація демо на Render

Репозиторій містить `render.yaml` для одного Node Web Service. Build використовує `npm ci --include=dev`, бо TypeScript, Vite і runtime `tsx` зафіксовані як dev-залежності, а сервіс запускається з `NODE_ENV=production`. Production-сервер бере порт із `PORT`, слухає `0.0.0.0`, віддає зібраний `dist` і приймає same-origin запити API. Якщо frontend розміщено на іншому домені, додайте його повний origin у `ALLOWED_ORIGINS`; кілька адрес розділяються комами.

1. Створіть приватний або публічний GitHub-репозиторій і завантажте цей проєкт.
2. У Render виберіть **New → Blueprint**, підключіть репозиторій і підтвердьте конфігурацію з `render.yaml`.
3. Після завершення build відкрийте видану адресу `https://...onrender.com`.

Без `BLENDER_PATH` серверний Cycles буде недоступний, але редактор, SVG → 3D та браузерне завантаження кадру працюють. Free Web Service засинає після періоду бездіяльності, а локальні файли не зберігаються між перезапусками; для цього демо вони не є джерелом стану.
