## Ще не підтверджено

### Перевірка навантаження у спокої, 2026-10-04

Користувач повідомив про сильне навантаження навіть без взаємодії. У свіжому запуску локального редактора цей симптом не відтворився: діагностичний лічильник після ініціалізації залишився на 2 кадрах до змін оптимізації. Активного процесу Blender не виявлено. За окремий 10-секундний інтервал доступні Node-процеси показали 0.00 CPU-секунд із точністю виводу; це не вимір GPU або всього браузера. Початково локальний сервер не працював; його запущено для перевірки. Sandbox-запуск tsx завершувався помилкою системного userInfo; поза sandbox запуск успішний, тому це не доказ фізичної нестачі RAM.

Виправлено зайву роботу: об’єднання запитів кадру через requestAnimationFrame без постійного циклу, скасування запланованого кадру для прихованої вкладки, resize лише за зміни розмірів, pixel ratio до 1, збереження матеріалів і джерел під час зміни ракурсу. Параметри Cycles та контракт сцени не змінено.

Після змін: npm test — 14/14, build і TypeScript — успішні; попередження про розмір bundle залишається. У живому WebGL перевірено скло, метал, хром, aspect 1:1, заміну знака кільцем та reset view. Лічильник після вибору скла залишився 3 → 3 між спостереженнями без взаємодії. Консоль браузера без warn/error. [Збережений знімок](../.local/verification/idle-performance.jpg) візуально переглянуто. Пауза прихованого перегляду, об’єднання кадрів і dispose перевірені unit-тестами планувальника; окреме перемикання видимості браузера не вимірювалося. Cycles повторно не запускався, оскільки його код не змінювався.

Причина навантаження у початковій сесії користувача залишається непідтвердженою. Не виміряні GPU utilization, загальний CPU браузера, поведінка у браузері користувача та виграш на екрані з DPR 2. Для повторного випадку потрібні браузер/відкрита адреса та процес, що навантажує CPU/GPU в цей момент.

### Попередні відкриті перевірки

- Збіг проєкції між рушіями з числовою похибкою до 1 px.
- Калібрована відповідність яскравості та матеріалів browser/Cycles.
- Поглинання скла за еталонними товщинами. Відображення sigma в Volume Absorption виправлено за реалізацією Cycles: color=1-sigma/max(sigma), density=max(sigma); окремий фізичний тест попереду.
- Повна матриця JPG/PNG/alpha × п’ять aspect на GPU. Автоматичні тести перевіряють обчислення розмірів; наскрізний 4К-прогін виконано для PNG 16:9.
- Завантаження довільних складних користувацьких логотипів; потрібні реальні зразки.
- Якість малих фасок/гострих кутів, UV/tangents для текстур і каустики.

Початковий studio preset тепер використовує синій фон, холодне заповнення, теплий key та виразне контрове світло, щоб наблизити візуальну подачу до погодженого референсу. Це змінює стартовий вигляд, але не змінює scene schema чи фінальну роздільність. Перший наступний етап: калібрування світла й матеріалів на затверджених користувачем референсах, із кількома реальними SVG. Production auth, збереження проєктів і черги розробляються після цієї перевірки.

### Volumetric lighting

Додано `Scene.volumetrics`: `enabled`, `density`, `anisotropy`, `intensity`. У UI це один перемикач «Об’ємне світло». WebGL показує м’яке геометричне наближення променів уздовж джерел; Cycles використовує обмежений Principled Volume навколо об’єкта та камери й слабкий compositor FOG_GLOW на яскравих відбиттях. Нескінченний World Volume відхилено після візуального тесту, бо він поглинав фон уздовж camera ray.

На MX230 перевірено два Cycles preview з увімкненою опцією: bounded medium завершився за 17.09 с, фінальний варіант із camera response — за 16.89 с при 960 × 540 і 64 samples. Збережений результат із glow: `.local/jobs/433523c1-9a68-412e-be09-6636c8a7f935/result.png`. Glow видно по верхньому контуру та внутрішній фасці; це підтверджує camera response, але не є вимірюванням оптичної системи реальної камери. Щільність стартова й потребує калібрування на склі, металі та різних фонах.
